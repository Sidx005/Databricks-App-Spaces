# Unity Catalog Data Access and Authorization Testing

## 1. Objective

To understand how Databricks App Spaces, app-sharing permissions, OAuth On-Behalf-Of (OBO) authorization, and Unity Catalog permissions work together to enforce user-specific data access.

### Expected Outcomes

1. Both Sales and Finance users can access the same application.
2. Sales users can query the Sales dataset but cannot query the Finance dataset.
3. Finance users can query the Finance dataset but cannot query the Sales dataset.

## 2. Environment Configuration

| Configuration | Value |
|---|---|
| Workspace | Existing Databricks trial workspace |
| App Space | `Sales-Insights-Demo` |
| RBAC | Any role |
| API Scopes | Data + AI |
| Serverless Policy | None |
| Catalog | `workspace` |
| Sales Schema | `sales_demo` |
| Finance Schema | `finance_demo` |

## 3. Data Structure

Both datasets reside in separate schemas under the same `workspace` catalog. Each table contains 100 rows of sample data.

### 3.1 Sales Dataset

**Table:** `workspace.sales_demo.sales_data`

Contains sample sales transaction records with the following columns:

| Column | Description |
|---|---|
| `order_id` | Unique identifier for each order |
| `order_date` | Date of the order |
| `region` | Geographical sales region |
| `customer_segment` | Customer classification |
| `product_category` | Category of the product sold |
| `sales_channel` | Channel through which the sale was made |
| `revenue` | Revenue generated by the order |
| `quantity` | Quantity of products sold |
| `sales_target` | Target sales amount |

### 3.2 Finance Dataset

**Table:** `workspace.finance_demo.finance_data`

Contains sample expense transaction records with the following columns:

| Column | Description |
|---|---|
| `transaction_id` | Unique identifier for each transaction |
| `transaction_date` | Date of the transaction |
| `department` | Department incurring the expense |
| `expense_category` | Category of the expense |
| `cost_center` | Cost center associated with the expense |
| `amount` | Actual expense amount |
| `budget` | Budget allocated for the expense |

## 4. Authorization Testing Overview

The experiment uses the two datasets to validate whether Unity Catalog enforces data access according to the signed-in user's permissions.

- **Sales user:** Can access `workspace.sales_demo.sales_data` but should be denied access to `workspace.finance_demo.finance_data`.
- **Finance user:** Can access `workspace.finance_demo.finance_data` but should be denied access to `workspace.sales_demo.sales_data`.

Both users share access to the same application. Data access is controlled separately through Unity Catalog permissions and the application's authentication and authorization flow.



## 5. Permissions Grant Commands
```sql
GRANT USE CATALOG ON CATALOG workspace
TO `demo-sales-users`;

GRANT USE CATALOG ON CATALOG workspace
TO `demo-finance-users`;

GRANT USE SCHEMA ON SCHEMA workspace.sales_demo
TO `demo-sales-users`;

GRANT SELECT ON TABLE workspace.sales_demo.sales_data
TO `demo-sales-users`;

GRANT USE SCHEMA ON SCHEMA workspace.finance_demo
TO `demo-finance-users`;

GRANT SELECT ON TABLE workspace.finance_demo.finance_data
TO `demo-finance-users`;


SHOW GRANTS ON TABLE workspace.sales_demo.sales_data;

SHOW GRANTS ON TABLE workspace.finance_demo.finance_data;
```
